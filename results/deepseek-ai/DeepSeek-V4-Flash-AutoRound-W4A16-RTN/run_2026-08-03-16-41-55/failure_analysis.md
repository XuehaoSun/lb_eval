## Root Cause

The quantized DeepSeek-V4-Flash model (43 MoE layers × 256 experts, each expert is a 2048×4096 + 4096×2048 pair) cannot fit in the 139.81 GiB GPU during lm_eval's `from_pretrained` load. Even with W4A16 RTN quantization, the full unfused-expert materialized checkpoint plus the lm_eval/HF Transformers loading materializer (concurrent.futures thread pool) requires more VRAM than available.

## Traceback Analysis

lm_eval's `simple_evaluate` → HuggingFace model `create_from_arg_obj` → `huggingface._create_model` → `AUTO_MODEL_CLASS.from_pretrained` → `transformers.modeling_utils._load_pretrained_model` → `convert_and_load_state_dict_in_model` (in `core_model_loading.py`) which uses a thread pool (`concurrent.futures`) to materialize and copy tensors via `_materialize_copy` (`tensor.to(device, dtype)`). The fault is in this materialization step: the 256-expert DeepseekV4Experts blocks produce enormous tensors that overflow the single 140 GB GPU. The fault is environmental/resource, not in any library code per se — but it is triggered by auto_round's choice to leave experts unfused (43 MoE modules × 256 experts materialized simultaneously in Transformers' loading materializer).

## Suggested Fix

1) Set `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` and pass `device_map='auto'` / `low_cpu_mem_usage=True` to lm_eval. 2) Use a multi-GPU setup: run with `CUDA_VISIBLE_DEVICES=0,1` (or more) so the ~140 GB of expert weights can be sharded across devices. 3) Configure lm_eval with `--model hf` plus `device_map=balanced` or enable `max_memory` mapping. 4) If single-GPU, requantize with auto_round enabling MoE expert fusion (`--enable_moe_fuse` or equivalent) so experts are packed into a single Linear per layer rather than 256 separate _ExpertContainer modules — this dramatically reduces HF loading overhead. 5) As a last resort, use lm_eval with `dtype=bfloat16` and add `attn_implementation=eager` to reduce peak transient memory.

## Workaround

Evaluate on CPU (slow but works) with `--device=cpu`, or use a smaller calibration/eval batch, or shard the model with `device_map='balanced_low_0'` across 2× A100/H100 80GB nodes. Alternatively, requantize enabling MoE expert fusion to reduce the number of Linear layers loaded.
